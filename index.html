Capstone

StatusGrep

HTTP monitoring, incident response, and public status communication for small teams.

Product

What it does

  • Schedules HTTP checks against registered endpoints
  • Derives service health from consecutive results
  • Opens incidents and alerts on outage
  • Publishes selected services on a public status page
  • Enforces plan limits with Paystack checkout

Domain

Service status

Operational Degraded Outage Unknown
  • Operational — check rules satisfied through the recovery threshold
  • Degraded — reachable but not fully healthy
  • Outage — consecutive failures reached the fail threshold
  • Unknown — no usable recent results

Domain

Incident lifecycle

Investigating→ Identified→ Monitoring→ Resolved
  • Opened automatically when status becomes Outage
  • At most one active incident per service
  • Status advances only forward
  • Acknowledge records that an alert was seen; it does not resolve the incident

Domain

Access

Owner Responder Viewer Platform admin
  • Owner — services, members, plan, overrides
  • Responder — incidents, alerts, acknowledgement
  • Viewer — read access within the project
  • isPublic — presence on the public status page

Verification

Acceptance scenarios

Seven end-to-end behaviours the system must satisfy. The next slides state each scenario in turn.

01 / 07

Healthy endpoint → Operational

A reachable endpoint with successful checks records results and shows Operational on the service and project views. Public services appear on the public status page.

02 / 07

Fail threshold → one Outage, one alert

When consecutive failures reach the fail threshold, the service enters Outage. A single incident and a single alert are created for that continuous outage—not one per failed check.

03 / 07

Recovery threshold → Operational

After Outage, status returns to Operational only after the configured number of consecutive successful checks—not after a single success.

04 / 07

Retries without duplicates

Scheduler and worker retries must not produce duplicate results or alerts for the same state. Uniqueness is enforced in the database.

05 / 07

Failed mail is retried

Delivery failures remain in the outbox with backoff. Messages are marked delivered only after a successful send. Acknowledgement is independent of delivery.

06 / 07

Private services stay private

Services with isPublic false are omitted from the public status surface. Project members retain access in the authenticated UI.

07 / 07

Plan payment is verified once

Failed or abandoned checkout leaves limits unchanged. Successful Paystack payment is verified before upgrade; idempotency prevents applying the plan twice.
